Intro

Dig is a music search platform built on public Discogs catalog data. Structured, accurate, explainable music data - for humans and agents - from one retrieval core.

Architecture

One codebase. One retrieval core.

One codebase. The web app, the MCP server, and the editorial admin all call the same domain services. Agent answers and UI results are always aligned because they come from the same place.

Data strategy

Normalisation decisions before importer code.
No exceptions.

Discogs XML dumps are the foundation - CC0 licensed, full catalog, no API dependency. The risk isn't getting the data. It's normalising it correctly. The importer is driven by a profiling-backed normalisation dictionary written against real dump samples, not assumptions.

01

Raw payload staging is non-negotiable

Store parsed entities in ingest.raw_entities before normalisation. Canonical tables can be re-derived as the schema evolves. Skip this and you're rewriting the importer from scratch every time something changes.

02

Messy fields stay raw in v1

Preserve raw credit role strings, identifier values, and track positions. Parse conservatively. Add normalised helpers later.

03

Load-bearing edge cases

ANV handling, track position encoding, credits nesting, and master/release linkage are all profiled before importer logic is locked.

04

Search starts in Postgres

tsvector + pg_trgm first. OpenSearch only when measured relevance or latency makes the migration worth it.

Build plan

Risk-first. Data decisions before infrastructure ambition.

Pre-M0

Profile real Discogs dump samples

Profile real Discogs dump samples. Write the normalisation dictionary. Lock the schema before the importer is written.

M1

Ingestion foundation

Schema migrations, raw_entities staging, parser pipeline, canonical upserts, QA reports.

M2

Search + read API

Postgres FTS, core entity endpoints, mobile-first UI prototype.

M3

Curation + media links

Curators, crates, link provenance, editorial tooling.

M4

MCP layer

Agent tools on the same domain services as the REST API. Provenance and confidence in every response.

M5

Matching + export

Track matching to Spotify and Apple Music, confidence scoring, export jobs.

M6

Search cluster decision gate

OpenSearch only if the metrics justify it.

Defaults
Architecture — Modular monolith
Search v1 — Postgres FTS + pg_trgm
Ingest — Raw payload staging in ingest.raw_entities
Auth v1 — Editorial-only
LLM strategy — No proxying. Expose MCP/API, users bring models
Non-goals — Marketplace, compliance stack, Discogs write-back
